# RPHC Smart Management System — ต้นแบบ (Prototype)

ต้นแบบระบบบริหารจัดการภายในโรงพยาบาลส่งเสริมสุขภาพตำบล ครบทั้ง 10 ระบบงาน
พร้อม Dashboard ผู้บริหาร, ผู้ช่วยร่างรายงาน, Audit Log และระบบสิทธิ์ตามบทบาท

โฟลเดอร์นี้พร้อม deploy ขึ้น Vercel ได้ทันที ไม่ต้อง build ไม่ต้องติดตั้ง dependency ใดๆ

---

## วิธี Deploy ขึ้น Vercel

### วิธีที่ 1: ลากโฟลเดอร์ขึ้นเว็บ (ง่ายที่สุด ไม่ต้องใช้คำสั่ง)

1. เข้า https://vercel.com/new
2. ลากโฟลเดอร์ `work system` ทั้งโฟลเดอร์ไปวางในหน้าเว็บ
3. กด **Deploy** — เสร็จภายในไม่กี่วินาที

Vercel จะตรวจพบเองว่าเป็นเว็บ static (เพราะไม่มี `package.json`) และเสิร์ฟไฟล์ให้เลย
ไม่ต้องตั้งค่า Build Command หรือ Output Directory ใดๆ

### วิธีที่ 2: ใช้ Vercel CLI

เปิด PowerShell หรือ Command Prompt แล้วพิมพ์:

```powershell
npm i -g vercel
cd "C:\work system"
vercel --prod
```

ครั้งแรกจะให้ล็อกอินก่อน จากนั้นตอบคำถามดังนี้:

| คำถาม | ตอบ |
|-------|-----|
| Set up and deploy? | **Y** |
| Which scope? | เลือกบัญชีของคุณ |
| Link to existing project? | **N** |
| What's your project's name? | ตั้งชื่อตามต้องการ เช่น `rphc-system` |
| In which directory is your code located? | **./** (กด Enter) |
| Want to modify these settings? | **N** |

### วิธีที่ 3: ผ่าน GitHub (แนะนำถ้าจะแก้ไขต่อเนื่อง)

```powershell
cd "C:\work system"
git init
git add .
git commit -m "RPHC Smart Management System prototype"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ-repo>.git
git push -u origin main
```

จากนั้นเข้า https://vercel.com/new → Import repo ที่เพิ่ง push → กด Deploy
ครั้งต่อไปแค่ `git push` ระบบจะ deploy ให้อัตโนมัติ

### ทดสอบในเครื่องก่อน deploy

```powershell
cd "C:\work system"
npx serve .
```

แล้วเปิด http://localhost:3000

> **อย่าเปิดไฟล์ `index.html` ด้วยการดับเบิลคลิกตรงๆ** เพราะเบราว์เซอร์จะบล็อกการโหลดไฟล์ในโฟลเดอร์ `assets/` ทำให้หน้าจอว่างเปล่า ต้องเปิดผ่านเว็บเซิร์ฟเวอร์เสมอ

## โครงสร้างไฟล์

```
work system/
├── index.html              หน้าเว็บหลัก
├── vercel.json             ตั้งค่า Vercel (cache ไฟล์ไลบรารี)
├── .gitignore              สำหรับกรณีใช้ git
├── README.md               ไฟล์นี้
└── assets/
    ├── data.js             โครงสร้างข้อมูล 10 โมดูล + ข้อมูลตัวอย่าง + สิทธิ์แต่ละบทบาท
    ├── app.js              ตรรกะทั้งหมด (CRUD, dashboard, รายงาน, audit log)
    └── vendor/
        ├── tailwind.css    ไฟล์ CSS (build ไว้แล้ว)
        └── chart.umd.js    ไลบรารีกราฟ Chart.js
```

**ไม่มีการเรียก CDN ภายนอกใดๆ** (ยกเว้นฟอนต์ไทยจาก Google Fonts) ระบบจึงทำงานได้แม้อยู่ในเครือข่ายปิดของหน่วยงาน

## จะแก้ไขอะไร ต้องแก้ไฟล์ไหน

| ต้องการแก้ | ไฟล์ | จุดที่แก้ |
|-----------|------|----------|
| เพิ่ม/ลบ/เปลี่ยนชื่อคอลัมน์ในแต่ละระบบ | `assets/data.js` | ตัวแปร `MODULES` |
| เปลี่ยนข้อมูลตัวอย่าง | `assets/data.js` | ตัวแปร `SEED` |
| เปลี่ยนสิทธิ์ว่าบทบาทไหนเห็นระบบใด | `assets/data.js` | ตัวแปร `ROLE_ACCESS` |
| เปลี่ยนบทบาทที่แก้ไขข้อมูลไม่ได้ | `assets/data.js` | ตัวแปร `READONLY_ROLES` |
| เปลี่ยนตัวเลข/กราฟบน Dashboard | `assets/app.js` | ฟังก์ชัน `renderDashboard` |
| เปลี่ยนแม่แบบรายงาน | `assets/app.js` | ฟังก์ชัน `runAI` |
| เปลี่ยนสีธีม | `assets/app.js` | ค้นหา `#1F7A6C` (เขียวหลัก) และ `#123b34` (เขียวเข้มแถบเมนู) |

การเพิ่มระบบใหม่ทั้งระบบทำได้โดยเพิ่ม key ใหม่ใน `MODULES` และ `SEED` แล้วเพิ่มชื่อ key นั้นใน `ROLE_ACCESS` ของบทบาทที่ควรเห็น — หน้าตาราง ฟอร์ม ค้นหา Export ทั้งหมดจะสร้างให้อัตโนมัติ

### ฟีเจอร์ที่ใช้งานได้จริงในทุกโมดูล

- เพิ่ม / แก้ไข / ลบข้อมูล พร้อมฟอร์มตรวจสอบค่าที่จำเป็น
- ค้นหาและกรองข้อมูลแบบทันที
- Export ออกเป็นไฟล์ CSV (เปิดใน Excel ได้ รองรับภาษาไทย)
- พิมพ์รายงาน / บันทึกเป็น PDF
- บันทึกทุกการกระทำลง Audit Log อัตโนมัติ

### ระบบสิทธิ์ตามบทบาท (8 บทบาท)

เปลี่ยนบทบาทได้จากกล่องเลือกมุมขวาบน เพื่อดูว่าผู้ใช้แต่ละกลุ่มเห็นเมนูอะไรบ้าง

| บทบาท | สิทธิ์ |
|-------|-------|
| ผู้ดูแลระบบ | ทุกระบบ + Audit Log + ตั้งค่าระบบ |
| ผู้บริหาร รพ.สต. | ทุกระบบ + Audit Log (ดูอย่างเดียว) |
| เจ้าหน้าที่สำนักงาน | บุคลากร, อสม./ประชุม |
| เจ้าหน้าที่พัสดุ | คลังยา, คลังวัคซีน, ครุภัณฑ์, ยานพาหนะ |
| เจ้าหน้าที่สาธารณสุข | ระบาดวิทยา, อนามัยโรงเรียน, มาตรฐาน PCU |
| เจ้าหน้าที่การเงิน | แผนยุทธศาสตร์ |
| อสม. | อสม./ประชุม (ดูอย่างเดียว) |
| ผู้เกี่ยวข้องภายนอก | Dashboard เท่านั้น (ดูอย่างเดียว) |

## ⚠️ ข้อจำกัดสำคัญของต้นแบบนี้

**ยังไม่เหมาะสำหรับบันทึกข้อมูลจริงของผู้ป่วยหรือบุคลากร** เพราะ:

1. **ไม่มีฐานข้อมูลกลาง** — ข้อมูลเก็บใน localStorage ของเบราว์เซอร์แต่ละเครื่อง
   ใครเปิดเว็บก็จะเห็นข้อมูลชุดของตัวเอง ไม่แชร์กัน ล้าง cache แล้วข้อมูลหาย
2. **ไม่มีระบบล็อกอินจริง** — การสลับบทบาทเป็นเพียงการสาธิต ไม่มีการยืนยันตัวตน
   ใครก็เปลี่ยนเป็นผู้ดูแลระบบได้
3. **ไม่มีการเข้ารหัสข้อมูล** — ยังไม่ผ่านมาตรฐาน PDPA สำหรับข้อมูลสุขภาพ
4. **AI Assistant เป็นแบบ rule-based** — ดึงตัวเลขจริงจากข้อมูลในระบบมาเติมในแม่แบบรายงาน
   ยังไม่ได้เชื่อมต่อ AI/LLM จริง

> **หมายเหตุเรื่องความเป็นส่วนตัว:** เว็บที่ deploy บน Vercel จะเข้าถึงได้จาก URL สาธารณะ
> ถ้าไม่ต้องการให้คนนอกเห็น ให้เปิด **Vercel Authentication** ใน Project Settings → Deployment Protection

ใช้ต้นแบบนี้เพื่อ: ให้ทีมงานทดลองใช้และให้ความเห็น, นำเสนอผู้บริหาร/หน่วยงานต้นสังกัด,
และเป็นตัวอย่างประกอบ TOR เวลาคุยกับผู้พัฒนา

## สิ่งที่ต้องทำต่อเพื่อใช้งานจริง (Production)

1. **ฐานข้อมูลกลาง** — PostgreSQL หรือ MySQL พร้อม API (Node.js / Laravel / .NET)
2. **ระบบยืนยันตัวตน** — ล็อกอินด้วยรหัสผ่าน + จำกัดสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ (ไม่ใช่แค่ซ่อนเมนู)
3. **มาตรการ PDPA** — เข้ารหัสข้อมูล, บันทึก RoPA, แบบขอความยินยอม, นโยบายเก็บ/ทำลายข้อมูล
4. **ระบบสำรองข้อมูล** — backup อัตโนมัติทุกวัน พร้อมทดสอบกู้คืนเป็นระยะ
5. **เชื่อมต่อ 43 แฟ้ม / HDC** — สำหรับส่งข้อมูลให้หน่วยงานต้นสังกัด
6. **อัปโหลดไฟล์แนบ** — Word/Excel/PDF/รูปภาพ ตามที่ออกแบบไว้ในโปสเตอร์โครงการ
